# Phaser

Обобщение [[barrier|барьера]] из Java 7 (`java.util.concurrent.Phaser`, Doug Lea). Отличие от CyclicBarrier: число участников **меняется на ходу**, участник может **отметиться, не ожидая**, а сами фазы **пронумерованы** и доступны снаружи. В Go такого примитива нет, но идеи полезны при проектировании пошаговых систем.

Связанные заметки: [[barrier]], [[waitgroup]], [[once]], [[channels]].

## Понятия

- **Party**: участник. Зарегистрированные участники составляют число, которого фазер ждёт.
- **Phase**: номер текущего раунда, растёт на единицу при каждом продвижении. Это тот самый номер раунда из [[barrier]], только публичный.
- **Arrive**: отметиться в текущей фазе. Когда отметились все зарегистрированные, фаза продвигается.
- **Advance**: продвижение фазы. Перед ним вызывается хук `onAdvance(phase, registeredParties)`, который может вернуть `true` и завершить фазер.

## API

| Метод | Что делает |
|---|---|
| `register()` / `bulkRegister(n)` | добавить участников, можно из любого потока и в любой момент |
| `arrive()` | отметиться и **не ждать**, вернуть номер фазы |
| `arriveAndAwaitAdvance()` | отметиться и ждать продвижения, это `CyclicBarrier.await` |
| `arriveAndDeregister()` | отметиться и выйти из числа участников |
| `awaitAdvance(phase)` | ждать конца указанной фазы, **не отмечаясь**. Для наблюдателей |
| `getPhase()` | текущий номер фазы, отрицательный после завершения |
| `forceTermination()` | завершить: все ждущие просыпаются |
| `onAdvance(phase, parties)` | переопределяемый хук; по умолчанию завершает фазер, когда участников ноль |

## Чем это отличается от барьера

**Динамический состав.** CyclicBarrier создаётся на N и живёт с ним. В Phaser участник может присоединиться посреди работы (`register`) или уйти навсегда (`arriveAndDeregister`), и число, которого ждут, пересчитывается. Полезно, когда задачи порождают подзадачи, которые тоже должны синхронизироваться по фазам.

**Отметиться без ожидания.** `arrive()` позволяет сказать «я закончил шаг» и заняться чем-то ещё, а дождаться продвижения позже через `awaitAdvance(phase)`. Барьер такое не умеет: у него отметка и ожидание слиты в `Wait`.

**Наблюдатели.** `awaitAdvance` без регистрации: поток ждёт конца фазы, но фазер его не ждёт. Так главный поток может следить за прогрессом воркеров.

**Завершение.** Фазер умеет заканчиваться, и все ждущие тогда выходят. Хук `onAdvance` даёт естественное место для условия «сделали достаточно итераций» или «сошлись».

**Ярусы (tiering).** Фазеры собираются в дерево: дочерний регистрируется в родительском как один участник. Продвижение родителя происходит, когда продвинулись все дети. Так снимают конкуренцию за один счётчик при тысячах участников, та же идея, что древовидный барьер.

## Пример

```java
Phaser phaser = new Phaser(1) {           // 1: главный поток
    protected boolean onAdvance(int phase, int parties) {
        return phase >= ITERATIONS - 1 || parties == 0;
    }
};
for (Task t : tasks) {
    phaser.register();
    new Thread(() -> {
        do {
            t.step();
            phaser.arriveAndAwaitAdvance();
        } while (!phaser.isTerminated());
    }).start();
}
phaser.arriveAndDeregister();             // главный вышел, воркеры крутят фазы сами
```

## Устройство

Одно 64-битное слово `state`: номер фазы, число зарегистрированных, число ещё не пришедших, флаг завершения. `arrive` это CAS-цикл, уменьшающий «не пришедшие»; кто довёл до нуля, вызывает `onAdvance`, пересчитывает слово (фаза + 1, не пришедшие = зарегистрированные) и будит ждущих. Ждущие лежат в двух Treiber-стеках, чётный и нечётный по номеру фазы, чтобы участники следующей фазы не смешивались с текущей. Это тот же трюк с номером раунда, что в [[barrier]], доведённый до двух очередей.

## Аналог в Go

Стандартного нет. Собирается из мьютекса, номера фазы и канала на фазу:

- состояние под `sync.Mutex`: `phase`, `registered`, `unarrived`, `done chan struct{}` текущей фазы;
- `Register` увеличивает оба счётчика;
- `Arrive` уменьшает `unarrived` и возвращает текущий `done`; довёдший до нуля закрывает `done`, создаёт новый, увеличивает `phase`, сбрасывает `unarrived`;
- `AwaitAdvance` ждёт на возвращённом канале, желательно в `select` с `ctx.Done()`.

Закрытие канала как широковещательная побудка заменяет `futex.WakeAll`, а новый канал на каждую фазу заменяет номер раунда: у ждущих старой фазы в руках старый канал, который уже закрыт, у новых новый. См. [[channels]].

## Когда это нужно

Итеративные алгоритмы с переменным числом воркеров, поэтапные миграции, симуляции, где агенты появляются и умирают, тесты, где нужно ровно выстроить порядок событий в нескольких горутинах. В большинстве сервисов достаточно [[waitgroup]] или [[errgroup]] на каждый этап.
