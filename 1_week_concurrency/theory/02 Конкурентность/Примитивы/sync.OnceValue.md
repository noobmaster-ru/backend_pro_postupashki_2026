# sync.OnceFunc, OnceValue, OnceValues

Обёртки над [[once|sync.Once]], появившиеся в Go 1.21. Превращают функцию в другую функцию, которая выполнит оригинал ровно один раз и запомнит результат.

Связанные заметки: [[once]], [[go memory model]], [[atomic]].

## Три функции

```go
func OnceFunc(f func()) func()
func OnceValue[T any](f func() T) func() T
func OnceValues[T1, T2 any](f func() (T1, T2)) func() (T1, T2)
```

- `OnceFunc`: как `Once.Do`, но без отдельной переменной `Once`.
- `OnceValue`: ленивое вычисление одного значения. Классика для глобальных синглтонов.
- `OnceValues`: то же для пары, обычно `(T, error)`.

```go
var loadConfig = sync.OnceValues(func() (*Config, error) {
    return parse("config.yaml")
})

func handler() {
    cfg, err := loadConfig() // первый вызов парсит, остальные отдают кеш
}
```

## Чем отличается от Once.Do

| | `Once.Do(f)` | `OnceValue(f)` |
|---|---|---|
| Где хранится результат | в твоих переменных, за видимость отвечает `Do` | внутри замыкания |
| Разные `f` в разных вызовах | возможно и это источник ошибок: выполнится та, что первая | одна `f` фиксирована при создании |
| Паника в `f` | `Do` считается выполненным, следующие вызовы **молча** возвращаются | паника **повторяется** при каждом вызове |
| `runtime.Goexit` в `f` | `Do` считается выполненным | тоже повторяется |

Разница в панике принципиальна. С `Once.Do` вызывающий после чужой паники получит нулевые значения и не узнает, что инициализация провалилась. С `OnceValue` каждый вызывающий получит ту же панику и не сможет проигнорировать сломанное состояние.

## Устройство

Упрощённо `OnceValue`:

```go
func OnceValue[T any](f func() T) func() T {
    var (
        once   Once
        valid  bool
        p      any      // значение паники
        result T
    )
    g := func() {
        defer func() {
            p = recover()
            if !valid { panic(p) }   // пробросить дальше первому вызывающему
        }()
        result = f()
        f = nil                       // отпустить замыкание для GC
        valid = true
    }
    return func() T {
        once.Do(g)
        if !valid { panic(p) }       // повторить панику остальным
        return result
    }
}
```

Три детали:
1. `once.Do(g)` даёт все гарантии видимости [[once]]: результат виден любому вызывающему.
2. `f = nil` после успеха, чтобы захваченные `f` объекты могли собраться сборщиком мусора. Сам результат живёт, пока жива обёртка.
3. `valid` отличает «успешно вернулись» от «упали». `recover()` в defer ловит и панику, и `Goexit` (для него `p == nil`, поэтому в реальном коде есть отдельная проверка).

## Когда использовать

- Ленивые глобальные ресурсы: конфиг, пул соединений, скомпилированная регулярка, большая таблица.
- Дорогие вычисления, результат которых не меняется за время жизни процесса.
- Замена паттерна «глобальная переменная + `sync.Once` + функция-геттер» на одну строку.

Когда **не** использовать:
- Результат может устареть и его надо пересчитывать. Здесь нужен кеш с TTL или явный сброс, `Once` не сбрасывается.
- Инициализация зависит от аргументов. Обёртка не принимает параметров; для «один раз на ключ» нужна мапа Once'ов или `singleflight`.
- Нужно освободить память результата: обёртка держит его навсегда.
