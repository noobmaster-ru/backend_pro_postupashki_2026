# RCU и copy-on-write

*Read-Copy-Update*: схема синхронизации, в которой читатели **не берут замков вообще**, а писатель делает копию, меняет её и атомарно публикует указатель. Придумана для ядра Linux (Paul McKenney, 2002), где читателей на порядки больше писателей. В Go благодаря сборщику мусора та же идея сводится к `atomic.Pointer` и copy-on-write.

Связанные заметки: [[rwmutex]], [[atomic]], [[go memory model]], [[cache coherence]], [[sync.Map]].

## Проблема, которую решает

[[rwmutex|RWMutex]] позволяет читать параллельно, но каждый `RLock`/`RUnlock` это запись в общее слово. При коротких чтениях на многих ядрах кеш-линия счётчика становится узким местом, см. [[cache coherence]]. Хочется, чтобы чтение было **обычным чтением памяти**, без единой записи.

## Идея

Три шага писателя:
1. **Read**: прочитать текущую структуру.
2. **Copy**: сделать копию, внести изменения в копию. Старая версия не трогается.
3. **Update**: атомарно подменить указатель на новую версию.

Читатель загружает указатель и работает с той версией, которую получил. Она неизменяема, поэтому никакой синхронизации не нужно. Если во время чтения указатель подменили, читатель просто дочитывает старую версию.

Остаётся вопрос: **когда можно освободить старую версию?** Только когда её точно никто не читает.

## В ядре Linux

Сборщика мусора нет, поэтому RCU решает вопрос освобождения явно:

- `rcu_read_lock()` / `rcu_read_unlock()`: границы секции чтения. На большинстве конфигураций это **пустые операции** или запрет вытеснения, никаких атомиков.
- `rcu_assign_pointer()`: публикация нового указателя с барьером записи.
- `rcu_dereference()`: чтение указателя с барьером зависимостей.
- `synchronize_rcu()`: писатель ждёт **grace period**, момент, когда каждое ядро прошло через *quiescent state*, то есть точно вышло из всех секций чтения, начатых до подмены. После этого старую версию можно освобождать.
- `call_rcu(ptr, fn)`: то же асинхронно, освобождение произойдёт по колбэку.

Так устроены таблицы маршрутизации, dentry-кеш, списки процессов. Чтение стоит ноль, запись дорогая и редкая.

## В Go

Grace period не нужен: старая версия живёт, пока на неё есть ссылки, и сборщик мусора освободит её сам. RCU вырождается в паттерн:

```go
type Config struct { /* только чтение после публикации */ }

var current atomic.Pointer[Config]

// Читатель: одна атомарная загрузка, никаких замков.
func Get() *Config { return current.Load() }

// Писатель: копия, изменение, публикация. Писатели сериализуются мьютексом.
var writeMu sync.Mutex
func Update(mutate func(*Config)) {
    writeMu.Lock()
    defer writeMu.Unlock()
    old := current.Load()
    next := old.clone()
    mutate(next)
    current.Store(next)
}
```

Гарантии: `Store` и `Load` последовательно согласованы, поэтому читатель, увидевший новый указатель, видит и всё содержимое новой структуры. См. [[go memory model]].

До дженериков ту же роль играл `atomic.Value`.

## Правила

- **Опубликованная версия неизменяема.** Менять её после `Store` нельзя: читатели уже могут её видеть. Любое изменение это новая копия.
- **Писатели сериализуются.** Иначе два писателя скопируют одну версию и второй затрёт изменения первого. Либо мьютекс, либо CAS-цикл на указателе с повтором.
- **Глубокая копия там, где нужно.** Если структура содержит мапы или слайсы, которые будут меняться, копировать их тоже. Иначе новая версия делит изменяемое состояние со старой.

## Цена

| | RWMutex | RCU / COW |
|---|---|---|
| Чтение | 2 атомарные записи | 1 атомарное чтение |
| Запись | ждёт читателей, меняет на месте | копия O(n), не ждёт никого |
| Память | одна версия | несколько версий живут одновременно |
| Читатель видит | всегда свежее | возможно, версию на момент загрузки |

RCU выигрывает при **редких записях и маленьких структурах** или когда структура и так копируется целиком: конфиг, флаги, таблица маршрутов, список обработчиков, снимок метрик. Проигрывает при частых записях в большую структуру: каждая запись копирует всё.

## Где встречается в Go

- `atomic.Pointer[Config]` для горячей замены конфига без рестарта.
- Старая реализация [[sync.Map]]: мапа `read` публикуется через атомарный указатель, читатели идут без замка.
- `http.ServeMux` в новых версиях, `slog` handlers, `expvar`.
- Иммутабельные структуры данных (persistent data structures), где копирование дешёвое из-за разделения неизменённых частей.

## Альтернативы без GC

Если сборщика мусора нет, а RCU не подходит, используют **hazard pointers** (читатель публикует указатель, который защищает) или **epoch-based reclamation** (освобождение откладывается на эпоху, когда все читатели гарантированно ушли). В Go они не нужны.
