# errgroup

`golang.org/x/sync/errgroup`: [[waitgroup]] плюс первая ошибка плюс отмена контекста плюс ограничение параллелизма. В прикладном коде для «запустить несколько подзадач и дождаться» нужен почти всегда он, а не голый `sync.WaitGroup`.

Связанные заметки: [[waitgroup]], [[worker pool]], [[channels]], [[once]], [[semaphore]].

## API

```go
g, ctx := errgroup.WithContext(parentCtx)
g.SetLimit(8)                       // не больше 8 активных горутин

for _, url := range urls {
    g.Go(func() error {
        return fetch(ctx, url)      // использовать ctx из WithContext
    })
}
if err := g.Wait(); err != nil {    // первая ненулевая ошибка
    return err
}
```

| Метод | Смысл |
|---|---|
| `errgroup.WithContext(ctx)` | группа и производный контекст, который **отменяется при первой ошибке** и при возврате из `Wait` |
| `g.Go(f)` | запустить `f` в горутине; при `SetLimit` блокируется, пока нет места |
| `g.TryGo(f)` | как `Go`, но при заполненном лимите вернуть `false`, не блокируясь |
| `g.SetLimit(n)` | максимум одновременных горутин; `-1` без лимита; менять можно только при нуле активных |
| `g.Wait()` | дождаться всех, вернуть первую ошибку |

Нулевое значение `errgroup.Group{}` работает без контекста: просто WaitGroup с первой ошибкой.

## Семантика

- **Только первая ошибка.** Остальные теряются. Если нужны все, собирать их самому под мьютексом или через `errors.Join`.
- **Отмена при первой ошибке.** Производный `ctx` отменяется, остальные горутины должны его проверять и выходить. errgroup их не убивает, это кооперативная отмена.
- **Wait всегда ждёт всех.** Даже после ошибки `Wait` вернётся только когда каждая горутина завершится. Горутина, которая игнорирует `ctx`, задержит всех.
- **Контекст отменяется после Wait.** Использовать `ctx` из `WithContext` после `Wait` нельзя: любой запрос с ним сразу упадёт с `context.Canceled`. Частая ошибка.
- **Паника в горутине.** В свежих версиях пакета (2025) паника или `runtime.Goexit` в горутине перехватывается и **перебрасывается из `Wait`** в вызывающую горутину, с типами `errgroup.PanicError` и `PanicValue`. Раньше паника просто роняла процесс из горутины, где стек не показывал вызывающего.

## Устройство

```go
type Group struct {
    cancel  func(error)          // отмена контекста
    wg      sync.WaitGroup
    sem     chan token           // семафор для SetLimit
    errOnce sync.Once            // первая ошибка
    err     error
}
```

- `Go`: если есть `sem`, отправить токен (блок при полном буфере), `wg.Add(1)`, запустить горутину; в ней `defer` снимает токен и делает `wg.Done()`, а при ошибке `errOnce.Do(func() { err = e; cancel(e) })`.
- `Wait`: `wg.Wait()`, затем `cancel(nil)`, вернуть `err`.

Три знакомых кирпича: [[waitgroup]], [[once]] и [[semaphore]] на буферизованном канале.

## Типичные применения

- **Параллельные запросы с общим дедлайном**: несколько бэкендов, первая ошибка отменяет остальные.
- **Ограниченный параллелизм** через `SetLimit` вместо ручного [[worker pool]].
- **Pipeline** из стадий, где падение одной стадии останавливает все.
- **Запуск серверов**: HTTP, gRPC, метрики в одной группе; падение любого останавливает остальные через `ctx`.

## Ловушки

> [!danger] Внешний ctx вместо производного
> Горутины берут `parentCtx`, а не `ctx` из `WithContext`. Отмена при первой ошибке не работает, остальные горутины продолжают до конца.

> [!danger] ctx после Wait
> После `g.Wait()` контекст мёртв. Для последующих операций нужен родительский.

> [!warning] Игнорирование ctx внутри горутин
> Если `f` не проверяет `ctx.Done()` и не передаёт `ctx` в IO, отмена бесполезна, `Wait` ждёт полного завершения.

> [!warning] Go после Wait
> Вызывать `g.Go` после начала `Wait` нельзя, как и `wg.Add` после `wg.Wait`.

## Сравнение

| | `sync.WaitGroup` | `errgroup.Group` | `conc.WaitGroup` |
|---|---|---|---|
| Ошибки | нет | первая | все или первая, настраивается |
| Отмена | нет | через ctx | через ctx |
| Лимит | нет | `SetLimit` | пул |
| Паники | роняют процесс | перебрасываются из `Wait` (новые версии) | перебрасываются |

С Go 1.25 у `sync.WaitGroup` появился метод `Go(f func())`, который делает `Add(1)` и `Done` сам, но ошибок и контекста там по-прежнему нет.
