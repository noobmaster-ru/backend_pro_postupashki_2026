# Атомики в Go

Операции над одним словом памяти, которые процессор выполняет неделимо: никто не увидит слово «наполовину записанным» и никто не вклинится между чтением и записью внутри одной операции. Пакет `sync/atomic`. На них построены все примитивы синхронизации: [[spinlock]], [[mutex]], [[semaphore]], [[waitgroup]], [[once]], [[rwmutex]], [[barrier]].

Связанные заметки: [[go memory model]], [[cache coherence]], [[RCU]], [[futex]].

## Набор операций

| Операция | Смысл | Типичное применение |
|---|---|---|
| `Load` | атомарно прочитать | флаги, быстрые пути |
| `Store` | атомарно записать | публикация значения |
| `Add(delta)` | прибавить, вернуть **новое** значение | счётчики, [[waitgroup]] |
| `Swap(new)` | записать, вернуть **старое** | освобождение замка с проверкой |
| `CompareAndSwap(old, new)` | если лежит `old`, записать `new`; вернуть, получилось ли | захват замка, lock-free структуры |
| `And`, `Or` (Go 1.23) | побитово, вернуть старое | флаги в одном слове |

Все операции в Go **последовательно согласованы** (*sequentially consistent*): нет вариантов relaxed/acquire/release, как в C++. Это проще и чуть дороже. См. [[go memory model]].

## Две формы API

**Функции с указателем** (старый стиль): `atomic.AddUint32(&x, 1)`, `atomic.LoadInt64(&n)`. Нужны, когда поле должно оставаться голым числом, например для [[futex]], которому нужен `*uint32`.

**Типы** (с Go 1.19, предпочтительны): `atomic.Int32`, `Int64`, `Uint32`, `Uint64`, `Uintptr`, `Bool`, `Pointer[T]`, `Value`. Методы те же. Плюсы: нельзя случайно обратиться неатомарно, `go vet` ловит копирование, и решена проблема выравнивания.

> [!warning] Выравнивание 64-битных атомиков
> На 32-битных платформах (386, arm, mips) 64-битная операция требует 8-байтового выравнивания, иначе паника. Голое поле `int64` в структуре может оказаться невыровненным; историческое правило «класть его первым в структуре». Типы `atomic.Int64` и `atomic.Uint64` выравниваются сами.

## atomic.Pointer и atomic.Value

`atomic.Pointer[T]` хранит `*T` и даёт `Load`, `Store`, `Swap`, `CompareAndSwap`. Основа паттерна copy-on-write и [[RCU]] в Go: читатели загружают указатель без замка, писатель собирает новую копию и подменяет указатель.

`atomic.Value` то же для `interface{}`, из догенериковых времён. Ограничение: все `Store` должны быть одного конкретного типа, иначе паника.

## Паттерн CAS-цикла

Любое «прочитать, посчитать, записать» над одним словом делается так:

1. `old := Load()`
2. вычислить `new` из `old`
3. `CompareAndSwap(old, new)`: успех → готово; провал → кто-то изменил слово, назад к шагу 1.

Так устроен вход читателя в [[rwmutex]] и захват разрешения в [[semaphore]]. Ключевое: писать `new` только относительно того значения, которое реально видели.

> [!warning] Проблема ABA
> CAS проверяет только равенство. Если слово изменилось A → B → A, CAS этого не заметит. Для счётчиков безобидно, для lock-free стеков и очередей с указателями опасно: указатель тот же, объект уже другой. Лечится тегом-версией в том же слове или, в Go, сборщиком мусора: пока кто-то держит старый указатель, адрес не переиспользуется.

## Как это устроено в железе

- **x86**: инструкции с префиксом `LOCK`: `lock xadd` для Add, `lock cmpxchg` для CAS, `xchg` для Swap. Обычные `mov` для Load и Store уже атомарны и упорядочены достаточно, Store в Go компилируется в `xchg`, чтобы дать seq_cst.
- **ARM64**: пара `ldaxr`/`stlxr` (load-linked/store-conditional) в цикле, либо инструкции LSE (`ldadd`, `cas`) на новых чипах.
- Любая атомарная запись требует монопольного владения кеш-линией, отсюда стоимость под конкуренцией. См. [[cache coherence]].

Порядок цен без конкуренции: обычная запись ≈ 1 нс, атомарная ≈ 5–20 нс. Под конкуренцией на общее слово рост в разы, независимо от того, атомик это или спинлок.

## Когда атомик, а когда мьютекс

**Атомик**, если инвариант умещается в одно слово: счётчик, флаг, указатель на неизменяемое состояние, состояние маленького автомата.

**Мьютекс**, если инвариант связывает несколько полей: «размер равен числу элементов», «баланс не отрицателен после перевода». Атомики по отдельности не защищают составные инварианты.

Атомики не быстрее мьютекса сами по себе. `sync.Mutex` без конкуренции это один CAS на вход и один Add на выход. См. [[sync.Mutex internals]].

## Ловушки

> [!danger] Смешивание атомарного и обычного доступа
> Если слово где-то читается через `atomic.Load`, писать его обычным присваиванием нельзя. Детектор гонок это поймает. Типизированные атомики физически не дают так сделать.

> [!danger] Атомарность не равна согласованности нескольких слов
> Два `atomic.Load` подряд читают два момента времени. Между ними другая горутина могла изменить оба слова. Снимок из нескольких полей делается через один указатель на неизменяемую структуру.
